# 已知限制

## 追踪范围

### async 函数与生成器不会被追踪

钩子只安装在创建协程/生成器的调用期间。函数体要等到 `await` 或迭代时才执行，此时钩子已经被移除。因此装饰 `async def` 或生成器函数不会产生任何追踪输出。

`Tracer` 上下文管理器仍可追踪 `with` 块内执行的代码，包括在其中显式进行的 `await` / 迭代。

### 函数按名称匹配

`trace_fn` 与 `trace_entity` 收集的是 `__name__`，而不是函数对象。不同模块中同名的函数无法被区分。

### 空追踪集合会追踪所有帧

如果装饰器既没有 `trace_entity=True` 也没有 `trace_fn`，或者上下文管理器的 `trace_fn=None`，追踪集合为 `None`，钩子生效期间执行的所有帧都会被追踪，包括标准库与第三方库的帧。

### 仅当前线程

`sys.settrace` 是线程局部的。其他线程中的工作不会被追踪。

## 输出

### 运行结束后才写出

追踪文本会先缓冲，在顶层运行结束时一次写出。Tracer 不是流式日志器：被追踪函数仍在执行时不会产生输出。

### 错误只报告，不抛出

失败的目标会被隔离并向 `stderr` 报告。非法路径或损坏的回调不会在装饰时失败，也不会中断被追踪函数；它们会在运行结束后以警告形式出现。若需要快速失败，请自行校验目标。

### 相对路径在写出时解析

文件目标在输出写出时打开，而不是在创建装饰器时打开。装饰与写出之间执行 `chdir()` 会改变相对路径的落点。

### JSON 导出是独立通道

`exception_json_path` 直接写入文件系统，不属于 `output_way`。它的失败同样以警告形式报告。

## 颜色

颜色能力在导入时基于 `sys.stderr` 检测一次。如果导入后再重定向流，已缓存的 `COLOR_SUPPORT` 不会重新计算。混合目标中只要包含文件或非终端流，颜色就会整体禁用。

## 运行开销

Tracer 使用 `sys.settrace` 并格式化每个调用与返回事件。它是诊断工具而非采样 profiler，不要在生产环境的热点路径上启用。

## 交互式调试

交互式 shell 参数已移除。请使用 Python 标准调试器：

```python
breakpoint()          # 或 pdb.set_trace()
```

## Python 版本

需要 Python 3.10.9 或更高版本。
